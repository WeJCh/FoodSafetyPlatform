# 接口契约与前后端联调信息提取

> 本文档仅做第三步信息提取，供后续重新设计前端时参考。不是最终 Stitch 输入文档，也不是 PRD。

## 1. 全局联调规则

### 1.1 网关与服务路由

| 网关前缀 | 目标服务 | 说明 |
|---|---|---|
| `/api/auth/**` | `user-service` | 登录、登出、验证、网关 introspect |
| `/api/users/**` | `user-service` | 用户注册、用户查询/更新 |
| `/api/roles/**` | `user-service` | 角色列表、用户角色绑定 |
| `/api/admin/**` | `user-service` | 系统管理员创建/删除监管账号 |
| `/api/regulation/**` | `regulation-service` | 企业、产品、监管员、区域、公告、预警代理 |
| `/api/files/**` | `regulation-service` | MinIO 上传预签名 |
| `/api/regulation-operation/**` | `regulation-operation-service` | 检查、抽检、整改、检查记录 |
| `/api/complaints/**` | `complaint-service` | 公众投诉与监管处理 |
| `/api/query/**` | `query-service` | 监管看板、预警统计 |
| `/api/warning/**` | `warning-service` | 网关已配置路由，但 `JwtAuthFilter` 明确禁止前端直连，外部应走 `/api/regulation/warnings/**` 代理 |

前端默认基础地址来自 `food-web/src/api/client.js`：`VITE_API_BASE || http://localhost:8080`。部分 API wrapper 允许使用 `VITE_REG_API_BASE`、`VITE_REG_OP_API_BASE`、`VITE_COMPLAINT_API_BASE` 覆盖服务地址，但默认仍建议走网关。

### 1.2 认证方式与请求头

| 类型 | 规则 |
|---|---|
| 前端认证头 | 受保护接口统一使用 `Authorization: Bearer <token>` |
| 网关 token 校验 | `JwtAuthFilter` 校验 JWT 签名，并调用 `user-service` 的 `/api/auth/introspect` 校验用户有效性 |
| 网关注入头 | 通过鉴权后注入 `X-User-Id`、`X-Username`、`X-User-Type`、`X-User-Roles` |
| 链路追踪 | 网关生成或透传 `X-Trace-Id`，响应头也返回 `X-Trace-Id` |
| 服务间调用 | 内部接口使用 `X-Internal-Token`，不应作为前端联调依赖 |
| 请求体 | 常规接口使用 JSON，前端 `request()` 默认加 `Content-Type: application/json` |
| CORS | 网关允许 `http://localhost:5173`，方法包括 `GET/POST/PUT/DELETE/OPTIONS`，允许 credentials |

### 1.4 统一返回与错误结构

| 类型 | 结构 |
|---|---|
| 业务成功返回 | `{ code: 0, message: "ok", data, timestamp }` |
| 业务失败返回 | `{ code, message, timestamp }` |
| 网关 401/403 | `{ code, message, traceId, timestamp }` |
| 分页结构 | `data.records`、`data.total`、`data.page`、`data.size`、`data.pages` |
| 前端解析规则 | HTTP 非 2xx 抛错；响应体 `code !== 0` 抛错；成功时返回 `data.data ?? data` |

错误码线索：

| code | 含义线索 |
|---|---|
| `0` | 成功 |
| `400` | 参数错误、校验失败、非法状态流转 |
| `401` | 未认证、token 无效、身份头缺失 |
| `403` | 无权限、数据范围越权、文件 bizType 越权 |
| `404` | `user-service` 的 `ErrorCode` 中存在，但跨服务使用情况待确认 |
| `500` | 服务端异常或 `IllegalStateException` |

待确认：仓库未发现跨服务统一的错误码字典；不同服务对校验错误信息的返回文本不完全一致。

| 预签名有效期 | `600` 秒 |
| `bizType` | `COMPLAINT`、`RECTIFICATION`、`INSPECTION` |
| `bizType` 权限 | `PUBLIC` 只允许 `COMPLAINT`，`ENTERPRISE` 只允许 `RECTIFICATION`；`INSPECTION` 当前对前端用户未放行 |
| 下载接口 | 待确认，未发现独立下载接口，当前通过 `fileUrl` 访问文件 |
| 导入/导出接口 | 待确认，未发现业务导入导出接口 |

### 4.6 统计数据范围控制

| 场景 | 规则线索 |
|---|---|
| 预警统计/监管概览 | `query-service` 使用 `X-User-Id`、`X-User-Type`、`Authorization` 应用数据范围 |
| 监管管理员 | 根据监管人员 `regionIds` 展开本辖区及下级辖区；如果未传 `regionId/regionIds`，服务端会补全允许范围 |
| 执法员 | 只能按自己的 `ownerRegulatorId` 查询；传入区域条件或他人 `ownerRegulatorId` 会返回 `403` |
| 非监管用户 | 网关层原则上不允许进入 `/api/query/**`，服务内非 `REGULATOR` 类型范围处理待确认 |
