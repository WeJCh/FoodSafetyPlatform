|------|------|

---

## 1. 部署概述

### 1.1 推荐方式：Docker Compose（全栈）

当前仓库提供完整 `docker-compose.yml`，一键启动：

- 基础设施：MySQL 8.0.39、Redis 7.2、Nacos 2.3.2、MinIO
- 业务服务：7 个 Spring Boot 微服务 + gateway
- 前端：food-web（Nginx 80，反代 `/api/` 至网关）

对外访问入口：**`http://{PUBLIC_HOST}:{WEB_HOST_PORT}`**（默认 80）。

### 1.2 备选方式：本机构建 + 上传虚拟机

适用于低配置演示机：在本机执行 `deploy/build/build-artifacts.ps1`（或 `.sh`）生成 jar 与 `food-web/dist`，再上传仓库与产物到服务器，在服务器执行 Compose 构建。详见 `deploy/build/README.md`。

> 早期 `docs/` 下部分部署说明曾描述「尚无 compose」，与当前仓库不符；以本文及根目录 `docker-compose.yml` 为准。

## 3. 部署前准备

### 3.1 获取代码

```bash
git clone <仓库地址>
cd food-safety-supervision-platform
```

### 3.2 配置环境变量

复制并编辑根目录 `.env`：

```bash
cp .env .env.local   # 可选备份
# 编辑 .env
```

**必改项（生产或公网演示）**：

| 变量 | 说明 |
|------|------|
| PUBLIC_HOST | 浏览器访问的主机 IP 或域名 |
| MYSQL_ROOT_PASSWORD、DB_PASSWORD | 数据库密码 |
| REDIS_PASSWORD | Redis 密码 |
| MINIO_ACCESS_KEY、MINIO_SECRET_KEY | 对象存储凭证 |
| REGULATION_INTERNAL_TOKEN、WARNING_INTERNAL_TOKEN | 服务间内部调用令牌 |
| jwt.secret（gateway application.yml 或环境覆盖） | JWT 密钥 |

**前端构建相关**（Compose 构建 food-web 时注入）：

- `VITE_API_BASE`、`VITE_REG_API_BASE`、`VITE_COMPLAINT_API_BASE`：应与 `PUBLIC_HOST` 一致，供浏览器访问 API。

**MinIO**：

- `MINIO_ENDPOINT`：容器内/服务间访问地址（Compose 网络内可用 `http://minio:9000`）
- `MINIO_PUBLIC_ENDPOINT`：浏览器访问附件的地址（常为 `http://{PUBLIC_HOST}:9000`）

### 3.3 本机构建 jar（Compose 构建需要）

在仓库根目录：

```powershell
# Windows
.\deploy\build\build-artifacts.ps1
```

或：

```bash
mvn -pl user-service,gateway-service,regulation-service,regulation-operation-service,complaint-service,query-service,warning-service -am package -DskipTests
cd food-web && npm ci && npm run build
```

确保各模块 `target/*-0.0.1-SNAPSHOT.jar` 存在后再 `docker compose build`。

## 4. Docker Compose 部署步骤

### 4.1 启动

在 `food-safety-supervision-platform` 根目录：

```bash
docker compose --env-file .env up -d --build
```

首次启动 MySQL 会执行 `deploy/mysql/init/*.sql` 初始化 6 库及演示数据。

### 4.2 验证

```bash
docker compose ps
```

| 检查项 | 方法 |
|--------|------|
| 前端 | 浏览器打开 `http://PUBLIC_HOST` |
| 网关 | 容器 `fsp-gateway-service` 运行中 |
| MySQL | `docker exec -it fsp-mysql mysql -uroot -p` 可登录 |
| Nacos | `http://PUBLIC_HOST:8848/nacos`（默认无鉴权，生产应开启） |
| MinIO 控制台 | `http://PUBLIC_HOST:9001` |

### 4.3 演示登录

账号见 `deploy/mysql/init/02-user-init.sql`，密码与用户名示例：

| 角色 | 用户名示例 | 密码 |

## 5. 服务与端口

### 5.1 容器清单

| 容器名 | 镜像/构建 | 宿主机端口（默认） |
|--------|-----------|-------------------|
| fsp-mysql | mysql:8.0.39 | 3306 |
| fsp-redis | redis:7.2-alpine | 6379 |
| fsp-nacos | nacos/nacos-server:v2.3.2 | 8848 |
| fsp-minio | minio | 9000 API、9001 控制台 |
| fsp-user-service 等 7 服务 | Dockerfile.backend | **不映射宿主机**（仅 fsp-net 内网） |
| fsp-gateway-service | Dockerfile.backend | 内网 8080 |
| fsp-food-web | food-web/Dockerfile | **80**（WEB_HOST_PORT） |

业务服务仅通过 Docker 网络 `fsp-net` 互访；外部只暴露 Web、MySQL、Redis、Nacos、MinIO（可按安全需求在 compose 中注释 `ports`）。

### 5.2 服务端口（容器内）

| 服务 | 端口 |
|------|------|
| gateway-service | 8080 |
| user-service | 8081 |
| regulation-service | 8082 |
| query-service | 8083 |
| warning-service | 8084 |
| complaint-service | 8085 |
| regulation-operation-service | 8086 |

### 5.3 Nginx 反代

`deploy/nginx/conf.d/default.conf`：

- `/` → 前端静态 `index.html`（SPA fallback）
- `/api/` → `http://gateway-service:8080`

## 6. 数据持久化与初始化

### 6.1 数据卷

| 卷名 | 用途 |
|------|------|
| mysql_data | 数据库文件 |
| redis_data | Redis AOF |
| minio_data | 对象存储 |

### 6.2 重新初始化数据库

MySQL 仅在**空数据目录**时执行 `/docker-entrypoint-initdb.d`：

```bash
docker compose down
docker volume rm food-safety-supervision-platform_mysql_data   # 卷名以 docker volume ls 为准
docker compose up -d
```

**警告**：删除卷将清空全部业务数据。

### 6.3 初始化脚本顺序

`deploy/mysql/init/01-user-schema.sql` … `11-warning-init.sql`（见《数据库设计说明书》）。

## 7. 日常运维

### 7.1 常用命令

```bash
# 查看日志
docker compose logs -f gateway-service
docker compose logs -f regulation-operation-service --tail 200

# 重启单个服务
docker compose restart user-service

# 停止全栈
docker compose down

# 更新代码后重建
docker compose up -d --build
```

### 7.2 健康检查

- 网关/服务：各服务若暴露 `/actuator/health` 或 `/api/health`（以实现为准）
- 登录页可正常登录即表示 user + gateway + mysql + redis 链路正常

### 7.3 备份建议

| 对象 | 方式 |
|------|------|
| MySQL | `mysqldump` 各 `food_*_db` 或卷快照 |
| MinIO | 卷备份或 `mc mirror` |
| 配置 | 备份 `.env` 与自定义 nginx 配置 |

### 7.4 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 前端 502 / API 失败 | gateway 或下游未就绪 | `docker compose logs gateway-service`；等待 Nacos 注册完成 |
| 登录 401 | Redis/MySQL 未就绪或密码错误 | 检查 user-service 日志与 `.env` |
| 附件无法访问 | MINIO_PUBLIC_ENDPOINT 配置错误 | 与浏览器可达地址一致 |
| 预警页面无数据 | regulation 代理或 warning 未启动 | 检查 warning-service、REGULATION/WARNING token |
| 数据库无演示数据 | 非首次启动未执行 init | 见 6.2 重建卷 |
| 内存不足 OOM | JVM/Nacos 过大 | 调小 `.env` 中 `JAVA_OPTS_*`、`NACOS_JVM_*` |

### 7.5 安全加固（生产）

1. 修改所有默认密码与内部 Token、JWT secret。
2. 关闭或限制 MySQL/Redis/Nacos/MinIO 的宿主机端口映射。
3. Nacos 开启鉴权。
4. 配置 HTTPS（在 Nginx 或前置负载均衡终止 TLS）。
5. 禁用网关 `GATEWAY_AUTH_INTROSPECT_FAIL_OPEN`（默认 false）。

## 8. 本地开发部署（非 Docker）

1. 启动 MySQL、Redis、Nacos、MinIO（可用 Compose 仅启基础设施：`docker compose up -d mysql redis nacos minio`）。
2. 执行 `deploy/mysql/init` 脚本建库。
3. 各服务 `application.yml` 中配置 `DB_HOST`、`REDIS_HOST`、`NACOS_ADDR` 等（默认可指向 `192.168.142.133`，需改为本机）。
4. 依次启动 7 个服务 + gateway。
5. `cd food-web && npm run dev`（5173），通过 Vite 代理或直连网关 8080。
