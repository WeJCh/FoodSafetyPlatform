## 4. 关键业务流程与状态流转线索

### 4.1 登录与分流

- `AuthView.vue` 登录后优先根据 `roles` 分流：`ADMIN`、`PUBLIC`、`REGULATOR_ADMIN/REGULATOR_ENFORCER`、`ENTERPRISE`。
- 若 `roles` 为空，旧前端按 `userType` 兜底分流。
- 监管用户进入 `App.vue` 后继续按监管角色分流到区域管理员或执法人员；若角色列表缺失，会调用监管档案接口兜底识别 `roleType`。

### 4.2 企业备案与产品档案

- 企业提交备案后状态进入 `PENDING`。
- 区域管理员可审批为 `APPROVED` 或 `REJECTED`，支持批量审批/驳回。
- 产品档案维护依赖企业备案审核通过；产品状态线索为 `ACTIVE` / `INACTIVE`。
- 监管任务创建时会要求企业为已审核通过状态。

### 4.3 检查任务与检查记录

- 检查任务状态线索：`CREATED -> ASSIGNED -> IN_PROGRESS -> COMPLETED -> CLOSED`。
- 区域管理员创建检查任务并指派执法人员；任务未过期且未开始/完成/归档时可派发。
- 执法人员只能执行分配给自己的任务：`ASSIGNED` 可开始，`IN_PROGRESS` 可提交检查结果。
- 提交检查结果时必须至少包含一个检查项。
- 检查结果或检查项为 `FAIL` 时会触发整改任务创建；连续不合格可能触发重点监管和预警。

### 4.4 抽检任务与结果公示

- 抽检任务状态线索：`CREATED -> ASSIGNED -> COMPLETED -> CLOSED`。
- 区域管理员创建抽检任务并指派执法人员；执法人员在 `ASSIGNED` 状态提交抽检结果。
- 抽检结果状态线索：`DRAFT -> PUBLISHED -> OFFLINE`。
- 公众端只查询 `PUBLISHED` 抽检结果。
- 抽检结果为 `FAIL` 时会标记重点监管企业并触发预警线索。

### 4.5 整改任务

- 整改状态线索：`ONGOING -> SUBMITTED -> CONFIRMED`，或 `SUBMITTED -> REWORK -> SUBMITTED`。
- 整改任务由检查不合格创建，初始为 `ONGOING`。
- 企业在 `ONGOING` 或 `REWORK` 状态提交整改说明和附件后进入 `SUBMITTED`。
- 区域管理员复核：`CONFIRM` 进入 `CONFIRMED`；`REWORK` 打回为 `REWORK`，且打回需填写意见。
- SLA 线索：企业首次提交期限 72 小时；监管复核期限 24 小时；打回后企业重新提交期限 48 小时。
- 整改动作日志线索：`SYSTEM_CREATE`, `ENTERPRISE_SUBMIT`, `REVIEW_CONFIRM`, `REVIEW_REWORK`, `SLA_OVERDUE_SUBMIT`, `SLA_OVERDUE_REVIEW`。

### 4.6 投诉流程

- 投诉状态线索：`SUBMITTED`, `PENDING`, `ASSIGNED`, `PROCESSING`, `FEEDBACKED`, `REJECTED`。
- 状态流转线索：
  - `SUBMITTED -> PENDING / REJECTED`
  - `PENDING -> ASSIGNED / REJECTED`
  - `ASSIGNED -> ASSIGNED / PROCESSING / REJECTED`
  - `PROCESSING -> FEEDBACKED / ASSIGNED`
  - `FEEDBACKED`、`REJECTED` 为终态
- 公众提交投诉后为 `SUBMITTED`，可匿名，可上传图片。
- 区域管理员受理后进入 `PENDING`，可派发给执法人员进入 `ASSIGNED`，也可驳回。
- 执法人员处理本人被派发投诉：`ASSIGNED -> PROCESSING -> FEEDBACKED`。
- 投诉达到配置阈值会触发企业重点监管线索：`COMPLAINT_OVERFLOW`。

### 4.7 风险预警

- 预警状态线索：`OPEN`, `PROCESSING`, `RESOLVED`, `CLOSED`。
- 预警动作线索：`EVENT_UPSERT`, `ASSIGN`, `PROCESS`, `RESOLVE`, `AUTO_LEVEL_UP`, `AUTO_ARCHIVE`。
- 区域管理员通过区域范围查询预警，可分派、处理、解决预警。
- 执法人员通过 `ownerRegulatorId` 查询自己相关预警，可处理、解决预警。
- `warning-service` 直接外部访问被网关禁止，外部监管端通过 `regulation-service` 代理访问。
- 自动归档、自动升级具体条件：待确认，需要继续阅读 `WarningEscalationScheduler.java`, `WarningArchiveScheduler.java`, `WarningEventServiceImpl.java`。

### 4.8 公告流程

- 公告状态线索：`DRAFT -> PUBLISHED -> OFFLINE`。
- 区域管理员创建/编辑草稿，发布后公众端可见，下线后不再作为公众公告展示。
- 公告是否支持分类、置顶、附件：待确认；当前组件文案提示“不扩展分类、置顶和附件”，但源码文本存在编码异常，需二次确认。

### 4.9 文件上传

- 文件业务类型线索：`COMPLAINT`, `RECTIFICATION`, `INSPECTION`。
- 当前权限线索：公众可上传投诉图片；企业可上传整改凭证。
- `INSPECTION` 上传业务入口：待确认，枚举存在但当前网关和 `FileController` 未放行监管角色。

### 4.10 重点监管企业

- 企业监管状态线索：`NORMAL`, `KEY`。
- 重点监管原因线索：`WARNING_TRIGGERED`, `COMPLAINT_OVERFLOW`, `CONSECUTIVE_FAIL`, `SAMPLING_FAIL`, `MANUAL_SET`。
- 自动触发线索：
  - 投诉超限：`ComplaintCommandService.java`
  - 连续检查不合格：`InspectionTaskServiceImpl.java`
  - 抽检不合格：`SamplingTaskServiceImpl.java`
