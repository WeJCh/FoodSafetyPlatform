# 食品安全监管平台 — 数据库设计说明书

| 项目 | 内容 |
|------|------|
| 系统名称 | 基于微服务的食品安全监管平台 |
| 文档版本 | V1.0 |
| 编写说明 | 以 `deploy/mysql/init/` 及各服务 `src/main/resources/sql/schema.sql` 为权威来源 |

---

## 1. 引言

### 1.1 编写目的

说明本平台在微服务架构下的数据库划分、表结构、逻辑关系及初始化策略，为开发、测试、部署与毕业设计验收提供数据层依据。

### 1.2 适用范围

适用于 `food-safety-supervision-platform` 仓库当前可运行版本，包含 6 个业务数据库、32 张业务表（含各库 `audit_log` 及 query 预留表）。

### 1.3 设计原则

1. **按服务分库**：每个微服务独立数据库，符合数据自治。
2. **逻辑关联**：跨库不使用物理外键，通过业务主键（如 `user_id`、`enterprise_id`、`biz_type+biz_id`）在应用层维护一致性。
3. **统一规范**：字符集 `utf8mb4`，排序规则 `utf8mb4_general_ci`；主键均为 `BIGINT` 自增；普遍使用 `deleted` 逻辑删除字段。
4. **可审计**：各业务库均设 `audit_log` 表，记录关键操作留痕。

## 2. 数据库总体设计

### 2.1 数据库清单

| 序号 | 数据库名 | 所属服务 | 表数量 | 说明 |
|------|----------|----------|--------|------|
| 1 | food_user_db | user-service | 4 | 用户、角色、审计 |
| 2 | food_regulation_db | regulation-service | 10 | 主数据、公告、重点监管 |
| 3 | food_regulation_operation_db | regulation-operation-service | 9 | 检查、抽检、整改、Outbox |
| 4 | food_complaint_db | complaint-service | 3 | 投诉及处理 |
| 5 | food_warning_db | warning-service | 3 | 预警规则、记录、日志 |
| 6 | food_query_db | query-service | 3 | **统计预留表，非主运行链路** |

### 2.2 初始化脚本

Docker / 本地首次建库执行顺序（`deploy/mysql/init/`）：

`01-user-schema` → `02-user-init` → `03-regulation-schema` → `04-regulation-init` → `05-operation-schema` → `06-operation-init` → `07-complaint-schema` → `08-complaint-init` → `09-query-schema` → `10-warning-schema` → `11-warning-init`

**注意**：MySQL 官方镜像仅在数据目录为空时自动执行；已有数据卷需删除后重建方可重新初始化。

## 3. 逻辑关系设计

### 3.1 跨库逻辑关联（无物理外键）

| 逻辑关联 | 说明 |
|----------|------|
| sys_user.id ↔ food_enterprise.user_id | 企业账号与备案主体 |
| sys_user.id ↔ food_regulator.user_id | 监管账号与监管档案 |
| food_enterprise.id ↔ 各业务 enterprise_id | 检查、抽检、投诉等业务对象 |
| food_product.id ↔ sampling_task.product_id | 抽检选品 |
| food_regulator.id ↔ assigned_to / inspector_id / handler_id | 任务指派与办理（ID 为监管人员档案 ID，非 user_id） |
| warning_record.(biz_type, biz_id) | 按类型关联整改、投诉、抽检等业务主键 |
| complaint.submitter_user_id ↔ sys_user.id | 公众投诉提交人 |

### 3.2 同库主要关系

- **regulation**：`addr_region` 自关联；`food_enterprise` → `region_id`、`address_id`；`food_product`、`enterprise_profile_attachment` 依赖 `enterprise_id`；`food_regulator_region` 关联监管员与辖区。
- **operation**：`inspection_task` → `inspection_record` → `inspection_item`；`inspection_record` 与 `rectification_task` 一对一（`uk_rectification_inspection`）；`sampling_task` → `sampling_result` 一对一（`uk_sampling_result_task`）。
- **complaint**：`complaint` → `complaint_handle` 一对一（`uk_complaint_handle`）。
- **warning**：`warning_record` → `warning_process_log`。

## 4. 分库表结构设计

### 4.1 food_user_db（user-service）

#### 4.1.1 sys_user（系统用户表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| username | VARCHAR(50) UK | 登录名 |
| password | VARCHAR(255) | BCrypt 密文 |
| real_name, phone | VARCHAR | 基本信息 |
| user_type | VARCHAR(20) | ADMIN / REGULATOR / ENTERPRISE / PUBLIC |
| status | TINYINT | 1 启用 / 0 禁用 |
| create_time, update_time, deleted | — | 审计与逻辑删除 |

#### 4.1.2 sys_role / sys_user_role

- 角色编码：`ADMIN`、`PUBLIC`、`ENTERPRISE`、`REGULATOR_ADMIN`、`REGULATOR_ENFORCER`（init 脚本插入）。
- `sys_user_role`：`uk_user_role(user_id, role_id)`。

#### 4.1.3 audit_log

记录用户注册、登录等审计；含 `before_data`/`after_data` 快照、`trace_id`。

---

### 4.2 food_regulation_db（regulation-service）

#### 4.2.1 主数据表

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| addr_region | 行政区划 | parent_id, name, level(1省2市3区县4街道) |
| addr_location | 详细地址 | region_id, detail |
| food_enterprise | 食品企业 | user_id(UK), enterprise_name, region_id, address_id, approval_status(PENDING/APPROVED/REJECTED), status(NORMAL/KEY), regulator_id |
| enterprise_profile_attachment | 备案附件 | enterprise_id, attachment_type, attachment_url |
| food_product | 产品档案 | enterprise_id, product_name, category, status(ACTIVE/INACTIVE) |
| food_regulator | 监管人员 | user_id(UK), role_type(REGULATOR_ADMIN/REGULATOR_ENFORCER) |
| food_regulator_region | 监管辖区 | regulator_id, region_id，UK(regulator_id, region_id) |

#### 4.2.2 enterprise_key_reason（重点监管原因）

记录企业被列为重点监管的原因：`COMPLAINT_OVERFLOW`、`CONSECUTIVE_INSPECTION_FAIL`、`SAMPLING_FAIL`、`RECTIFICATION_OVERDUE`、`MANUAL_SET` 等。

#### 4.2.3 public_bulletin（公众公告）

`status`：DRAFT / PUBLISHED / OFFLINE。

#### 4.2.4 audit_log

结构与 user 库类似，字段类型略有差异（JSON 快照）。

---

### 4.3 food_regulation_operation_db（regulation-operation-service）

#### 4.3.1 inspection_task（检查任务）

| 字段 | 说明 |
|------|------|
| status | CREATED → ASSIGNED → IN_PROGRESS → COMPLETED → CLOSED |
| assigned_to | 指派执法员（food_regulator.id） |
| enterprise_id, region_id | 企业与辖区 |

#### 4.3.2 inspection_record / inspection_item

- 记录：`task_id`, `inspector_id`, `result`(PASS/FAIL)。
- 明细：`inspection_id`, `item_name`, `item_result`。

#### 4.3.3 rectification_task / rectification_action_log

- 整改状态：ONGOING / SUBMITTED / REWORK / CONFIRMED。
- `inspection_id` 唯一对应一条整改（`uk_rectification_inspection`）。
- 动作日志：`SYSTEM_CREATE`、`ENTERPRISE_SUBMIT`、`REVIEW_CONFIRM`、`REVIEW_REWORK`、`SLA_OVERDUE_*` 等。

#### 4.3.4 sampling_task / sampling_result

- 抽检任务状态：CREATED → ASSIGNED → COMPLETED → CLOSED（无 IN_PROGRESS）。
- 结果：`result`(PASS/FAIL)，`public_status`(DRAFT/PUBLISHED/OFFLINE)，`uk_sampling_result_task(task_id)`。

#### 4.3.5 warning_event_outbox（预警事件出站表）

| 字段 | 说明 |
|------|------|
| event_key | 与 warning dedup_key 对齐 |
| status | PENDING / SENT / DEAD |
| payload_json | 投递 warning-service 的完整请求体 |

用于监管操作服务与预警服务之间的**最终一致性**投递，非消息队列。

---

### 4.4 food_complaint_db（complaint-service）

#### 4.4.1 complaint（公众投诉表）

`status` 枚举（应用层 `ComplaintStatus`）：

SUBMITTED → PENDING（受理）→ ASSIGNED → PROCESSING → FEEDBACKED；或 REJECTED。

关键字段：`submitter_user_id`、`enterprise_id`、`assigned_to`（执法员档案 ID）、`accepted_by`、`processed_by`、`deadline_time`。

#### 4.4.2 complaint_handle

`uk_complaint_handle(complaint_id)`：一条投诉一条处理记录。

---

### 4.5 food_warning_db（warning-service）

#### 4.5.1 warning_record

| 字段 | 说明 |
|------|------|
| dedup_key | UK，幂等去重 |
| level | L1 初发 / L2 升级加重 |
| status | OPEN / PROCESSING / RESOLVED / CLOSED |
| biz_type, biz_id | 关联业务对象 |
| region_id, owner_regulator_id, assigned_to | 权限过滤与分派 |

#### 4.5.2 warning_process_log

动作：EVENT_UPSERT、ASSIGN、PROCESS、RESOLVE、AUTO_LEVEL_UP、AUTO_ARCHIVE。

#### 4.5.3 warning_rule

规则配置表；当前以代码常量与事件驱动为主，表结构预留扩展。

---

### 4.6 food_query_db（query-service）

**重要说明**（与 `09-query-schema.sql` 注释一致）：

当前统计查询通过 **Feign 调用各服务 internal 统计接口** 聚合实现，**不依赖**下列预留表写入。

| 表名 | 说明 |
|------|------|
| stat_enterprise | 企业统计预留 |
| stat_inspection | 检查统计预留 |
| stat_complaint | 投诉统计预留 |

## 5. 索引与约束设计要点

| 类型 | 示例 |
|------|------|
| 唯一约束 | sys_user.username、food_enterprise.user_id、warning_record.dedup_key、rectification.inspection_id |
| 业务索引 | 任务 status、assigned_to、enterprise_id；预警 region/status 组合索引 |
| 逻辑删除 | deleted=0 为有效数据（查询需过滤） |
